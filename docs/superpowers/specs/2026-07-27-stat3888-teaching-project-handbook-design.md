# STAT3888 教学型项目手册 PDF 设计说明

## 1. 目标

制作一份中文为主、英文术语对照的教学型 PDF，使尚未学到基函数回归的学生能够：

1. 从已掌握的高等代数和概率论进入时空数据建模；
2. 理解为什么选择 `bicycle.csv` 和 Task 4；
3. 理解时空基函数回归的原理、假设、优势与局限；
4. 独立完成数据清洗、探索、建模、验证、解释与展示；
5. 将本项目积累的方法迁移到 GAM、正则化回归和后续机器学习课程。

PDF 不是项目答案代写，也不是只给代码的操作说明。它必须同时提供理论桥梁、完整流程、可运行代码、检查标准和展示策略。

## 2. 项目四个 Task 的教学解释

在进入选型前，PDF 必须完整解释原项目的 Task 1–4。不能只翻译任务名称，也不能因为最终选择 Task 4 就省略 Task 2 和 Task 3。

每个 Task 使用统一结构：

1. 一句话说明它在做什么；
2. 它试图回答哪类问题；
3. 输入数据必须具有什么结构；
4. 具体操作流程；
5. 输出是图、空间模式、插值结果还是预测模型；
6. 怎样判断结果是否正确；
7. 最适合四个数据集中的哪一个；
8. 优势、假设和局限性；
9. 在评分标准中怎样体现深度；
10. 与其他 Task 的区别和联系。

### 2.1 Task 1：Spatiotemporal Visualization

教学目标是让学生理解：时空可视化不是把经纬度画成散点，而是同时展示“在哪里、什么时候、数值多大以及怎样变化”。

PDF 需要解释：

- 空间地图、时间序列、分面地图、动画、时空热力图分别回答什么问题；
- 一个点、一种颜色、一个面板和一条线分别代表什么；
- 怎样固定颜色范围，使不同时间的地图能够比较；
- 怎样区分“数值为 0”和“没有观测”；
- 怎样从图中发现热点、趋势、季节性、异常和数据质量问题；
- 为什么可视化必须先于模型；
- 对 `bicycle.csv` 怎样制作月度趋势、季节图、社区热点图和社区 × 月份热力图；
- 什么属于描述性发现，什么不能被解释为因果关系。

### 2.2 Task 2：EOF Analysis

教学目标是让学生理解：EOF 把复杂的“时间 × 空间”矩阵分解为少数主要空间模式及其对应的时间变化。

PDF 需要解释：

- EOF 与 PCA、特征值、特征向量和 SVD 的关系；
- 如何构造时间 × 地点矩阵；
- 为什么需要中心化，什么时候需要标准化；
- EOF spatial pattern、PC time series 和 explained variance 分别是什么；
- 正负号为什么可以整体翻转；
- 第一模式解释方差最大为什么不等于具有因果意义；
- 怎样用空间载荷图、PC 时间序列和方差解释率图展示结果；
- 为什么规则、完整的空间面板最适合 EOF；
- EOF 适合发现共同变化模式，但不是直接的预测方法。

### 2.3 Task 3：IDW Prediction

教学目标是让学生理解：IDW 用附近已观测地点的值对未观测位置进行距离加权平均。

PDF 需要解释：

- “距离越近，权重越大”的直觉；
- IDW 公式中距离、权重和幂指数 \(p\) 的含义；
- 预测新地点与预测未来时间的区别；
- 怎样选择 \(p\) 和邻居数量；
- 为什么必须留出观测点并用交叉验证评价；
- RMSE 和 MAE 怎样衡量插值误差；
- 经纬度为什么不能在较大区域直接当作平面距离；
- IDW 不使用协方差模型，也通常不给可靠的不确定性；
- 当现象不满足空间平滑假设时，IDW 为什么可能失效；
- 为什么自行车盗窃事件数量不一定适合单纯的 IDW。

### 2.4 Task 4：Linear Regression with Basis Functions

教学目标是让学生理解：基函数先把原始时间和空间坐标转换成更丰富的特征，再使用对参数线性的回归模型表达非线性规律。

PDF 需要解释：

- 普通直线模型为什么不足以表示弯曲趋势、周期和空间热点；
- “对输入非线性、对系数线性”是什么意思；
- polynomial、B-spline、Fourier、radial basis 各自表达什么结构；
- 怎样从基函数得到设计矩阵；
- 基函数数量过多为什么会过拟合；
- Ridge 正则化怎样压缩系数并改善稳定性；
- 怎样使用时间外推和空间留出验证；
- 怎样比较简单基线与复杂模型；
- 怎样把模型预测反变换回盗窃次数；
- 怎样用时间效应图、预测地图和残差地图解释模型。

### 2.5 四个 Task 的递进关系

PDF 需要用一张流程图明确表示：

\[
\text{Task 1：看见时空规律}
\rightarrow
\begin{cases}
\text{Task 2：分解主要共同模式}\\
\text{Task 3：根据邻近观测插值}\\
\text{Task 4：用基函数建立解释和预测模型}
\end{cases}
\]

还要说明：

- Task 1 是所有方案的共同起点；
- Task 2 主要回答“有哪些主导模式”；
- Task 3 主要回答“未观测地点的值是多少”；
- Task 4 主要回答“时间、季节和空间结构能否解释并预测结果”；
- 三个选修任务不存在绝对新旧或高低，关键是研究问题、数据结构和验证是否匹配；
- 本项目选择 Task 4，是因为它与 `bicycle.csv` 的长时间跨度、固定社区位置和预测型研究问题最匹配。

## 3. 项目方案

### 3.1 数据与任务

- 数据：`bicycle.csv`
- 必做任务：Task 1 时空可视化
- 选修任务：Task 4 Linear Regression with Basis Functions
- 研究单位：社区 × 月份
- 响应变量：每个社区每月自行车盗窃次数
- 主研究问题：时空基函数能否预测社区层面的自行车盗窃数量，并解释盗窃活动随空间、季节和长期时间的变化？

### 3.2 主模型

主模型为正则化时空基函数回归：

\[
\log(1+y_{s,t}) =
\beta_0 +
B_{\mathrm{trend}}(t)\beta_t +
B_{\mathrm{season}}(t)\beta_s +
B_{\mathrm{space}}(lon_s,lat_s)\beta_g +
\varepsilon_{s,t}.
\]

其中：

- 长期趋势使用 B-spline 或自然样条；
- 年度季节性使用 Fourier 正弦/余弦基函数；
- 空间变化使用径向基函数或薄板样条；
- 多个基函数系数使用 Ridge 正则化控制复杂度；
- 普通线性模型作为题目合规基线，正则化模型作为现代化主模型。

### 3.3 验证设计

- 训练集：2014–2021；
- 验证集：2022；
- 最终测试集：2023；
- 使用滚动时间验证说明未来预测能力；
- 使用留出社区或空间分块作为空间泛化敏感性检查；
- 禁止随机拆分全部行，避免相邻月份和相同社区信息泄漏；
- 与全局均值、社区历史均值和简单季节模型比较；
- 评价指标包括 MAE、RMSE、测试集 \(R^2\) 与残差地图。

## 4. 教学设计原则

### 4.1 三层学习路线

每一章标记为：

- 核心路线：完成项目必须掌握；
- 进阶加分：提高方法深度与评分；
- 未来连接：本项目后续可迁移的方向，不要求当前完全掌握。

### 4.2 每个方法的固定解释模板

每个概念依次回答：

1. 它解决什么问题；
2. 输入和输出是什么；
3. 与已学知识怎样连接；
4. 公式中每个符号是什么；
5. 矩阵或向量维度是什么；
6. 为什么适合本数据；
7. 有什么优势和假设；
8. 什么情况下不能使用；
9. R 代码怎样对应公式；
10. 如何检查结果是否可信。

### 4.3 代码教学标准

- 核心代码可以从头到尾按顺序运行；
- 每段代码先写目的，再写代码，再解释关键对象；
- 不使用未说明来源的对象；
- 所有随机过程设置种子；
- 文件路径集中设置，不散落硬编码；
- 保存中间清洗数据、图表、模型和指标；
- 对常见错误给出症状、原因和修复方法；
- 核心实现依赖尽量少，进阶包明确标为可选。

## 12. 核心路径教学扩写

本次修订采用“核心代码逐行解释，其余代码按块解释”的分层实验手册结构。核心路径从打开
RStudio 开始，一直延伸到四页 PowerPoint 和最终提交检查，不能假定读者已经学过数据清洗、
回归、时间序列、空间统计或 GIS。

核心路径按以下顺序展开：

1. 建立 RStudio Project、确认工作目录、安装和加载软件包；
2. 读取 `bicycle.csv`，理解数据框、对象赋值和变量类型；
3. 审计日期、缺失值、重复行和季度字段；
4. 把事件表聚合为社区 × 月份面板；
5. 补齐零事件月份并验证 16,800 行；
6. 制作 Task 1 的时间、季节、空间和时空图；
7. 按年份划分训练、验证和测试集；
8. 构造 B-spline、Fourier、RBF 和社区指示变量；
9. 建立全局均值与社区均值基线；
10. 拟合 OLS 并解释设计矩阵、系数和预测；
11. 拟合 Ridge 并用验证集选择 λ；
12. 计算 MAE、RMSE 和 R²；
13. 绘制预测图与残差图并诊断遗漏结构；
14. 压缩为四页 PowerPoint；
15. 从空文件夹开始执行最终复现与提交检查。

每个步骤必须包含：

- “这一步解决什么问题”；
- “为什么必须在这里做”；
- 输入对象及其形状；
- 可直接运行的 R 代码；
- 核心行、函数和关键参数的逐项解释；
- 预期生成的对象、行数、图形或指标；
- 至少一个检查命令；
- 常见错误、错误原因和修正方法；
- 与评分标准或最终展示的连接。

例如，`bike <- readr::read_csv("bicycle.csv", show_col_types = FALSE)` 不能只作为代码块出现。
正文还要解释 `<-` 的对象赋值、`readr::` 的命名空间、相对路径的含义、
`show_col_types = FALSE` 只关闭提示而不改变数据，并要求通过 `dim(bike)` 和
`dplyr::glimpse(bike)` 检查读取结果。

## 13. 紧凑排版要求

- 保持单栏版式；
- 相邻标题、段落、代码、表格和提示框之间采用紧凑但可辨识的垂直间距；
- 不用大片留白分隔板块；
- 通过小标题、左侧色条、浅色底和字体层级区分“目的、代码、解释、检查、排错”；
- 核心代码使用略小但清晰的等宽字体，长代码允许自然分页；
- 表格行距压缩，但不得造成中文文字重叠或截断；
- 一个完整步骤尽量连续排布，无法容纳时允许自然跨页，不能强制整块换页制造空白；
- 扩写后的 PDF 仍需逐页渲染检查，确保无重叠、越界、黑块和过小文字。
